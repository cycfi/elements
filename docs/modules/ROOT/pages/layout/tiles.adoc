= Tiles

include::../common.adoc[]

== Overview

Tiles are the most useful layout elements. Tiles are used everywhere for
composing hierarchical elements in rows and columns, typical to all GUIs.
Tiles allow elements to fluidly adjust depending on available space. Tiles
compute the layout of its elements using the children elements' size
{limits}.

Each factory returns a `Composite`.

== Include

```c++
#include <elements/element/tile.hpp>
```

== htile

image::/layout/htile.svg[alt="htile", width=462px, role=center]

Horizontal Tiles allow elements to fluidly adjust horizontally depending on
available space.

image::/layout/htile_spaced.svg[alt="htile_spaced", width=578px, role=center]

Lays out the elements of a horizontal tile with a fixed space between each
element and the next.

=== Layout Rules

. The elements are laid out in a single row, left to right, immediately next
to each other with no intervening space.
. The elements are positioned horizontally using the children's natural
{limits}.
. Horizontal space is allocated using this algorithm:
 .. Space is allocated for each child element following the child's natural
_minimum horizontal limit_.
 .. If the allocated space exceeds the sum of all children elements'
__minimum horizontal limit__s, the extra space is given to each
horizontally resizable element (`limits.min.x < limits.max.x`).
 .. The element's "stretchiness" determines how much extra space is given
to it according to the element's `stretch()` member function. A stretch
value of `1.0` is default. A stretchiness value of 2.0 means that the
element is able to stretch twice as much compared to its siblings.
Horizontally fixed-sized elements will not be stretched (element d in
the diagram). (Also see {Stretch-Elements}).
. The tile's _minimum vertical limit_ is computed as the maximum of the
children elements' __minimum vertical limit__s.
. The tile's _maximum vertical limit_ is computed as the minimum of the
children elements' __maximum vertical limit__s.
. The final computed maximum limit is clamped to ensure it is not less
than the computed minimum limit: the minimum wins.
. The supplied (horizontal) and computed (vertical) coordinates may violate
the limits of its children elements.
 .. If the available size for a child element is lower than the element's
_minimum horizontal limit_, the element keeps its minimum and overflows past the
tile's end, without clipping.
 .. Along the tile, a child element stops at its _maximum horizontal limit_
and the leftover space stays at the end. Across the tile, a child element is
given the tile's full height.

=== Declaration

```c++
class htile_element : public composite_base
{
   ...
};

using htile_composite = vector_composite<htile_element>;

template <concepts::Element... E>
array_composite<sizeof...(E), htile_element>
htile(E&&... elements);

template <concepts::Element FE, concepts::Element... E>
array_composite<1+sizeof...(E), htile_element>
htile_spaced(float space, FE&& first, E&&... rest);
```

`htile` and `htile_spaced` return an `array_composite` and `htile_composite`
is a `vector_composite`, each with `htile_element` as its base. All of
`htile_element` is the `Composite` interface (see
xref:elements/composites.adoc[Composites]).

=== Expressions

==== Notation

`N`:: The number of items

`+e1,...eN+`:: One or more child elements, instances of `Element` (more below)

`space`:: `float`

`c`:: Instance of type `htile_composite`

==== Factory

[cols="1,1"]
|===
| Expression                    | Semantics

| `+htile(e1,...eN)+`
| Build a horizontal tile with a fixed number of elements. Elements
  `+e1,...eN+` are held in a `std::array<element_ptr, N>` managed by the
  horizontal tile element.
| `+htile_spaced(space, e1,...eN)+`
| The same as `+htile(e1, margin_left(space, e2),... margin_left(space, eN))+`
  (see xref:layout/margins.adoc#_margin_left[margin_left]): `space`
  between each element and the next.
|===

.Example
[,c++]
----
htile(item1, item2, item3, item4)
----

NOTE: If the number of elements is not fixed, you can use an
`htile_composite` (see below).

==== Constructors

[cols="1,1"]
|===
| Expression                    | Semantics

| `htile_composite c`
| Create a horizontal tile with an indeterminate (dynamic) number of
  elements.
|===

The `htile_composite` is essentially a `std::vector<element_ptr>` that the
client uses to manage the composite's elements. The client is responsible for
the lifetime of the container, `c`. You use `htile_composite` just as you
would a `std::vector`, such as using `push_back` to add a child element. Just
remember that the items are `element_ptr` instances.

.Example
[,c++]
----
c.push_back(share(child));
----

NOTE: `share` turns an element object into an `element_ptr` held by
the `std::vector<element_ptr>` in `htile_composite`.

`htile_composite` is itself also an `element` and while it has ``std::vector``'s
interface, it can also be ``share``d like any element, which allows you to
build complex hierarchical structures.

== Example

A column with a strip 30 high over two rows: one of two boxes 10 apart, the
second taking twice the extra width, and one of three boxes added at run
time:

```c++
#include <elements/element/tile.hpp>
#include <elements/element/size.hpp>        // For vsize and hstretch
#include <elements/element/style/misc.hpp>  // For box
...
using namespace cycfi::elements;
...
htile_composite swatches;                                <1>
for (auto fill : {colors::red, colors::green, colors::blue})
   swatches.push_back(share(box(fill)));

auto column = vtile(
   vsize(30, box(colors::slate_gray)),                   <2>
   htile_spaced(10,                                      <3>
      box(colors::gold),
      hstretch(2, box(colors::steel_blue))
   ),
   swatches                                              <4>
);
```

<1> A row whose boxes are added at run time.
<2> A strip 30 high.
<3> Two boxes 10 apart, the steel blue one taking twice the extra width.
<4> The row of three boxes, sharing the rest of the height equally with the
    row above.
