Advanced Builds

Overview

A first build needs nothing on this page: Setup and Installation builds Elements with each platform’s own host and drawing backend. This page is for changing that: which parts are built, which backend draws, which host runs the windows on Linux, and how to build with the sanitizers or link-time optimization.

Every choice here is made at configure time, with a -D option to cmake. Options are cached in the build directory, so give each configuration a build directory of its own.

Build Options

ELEMENTS_BUILD_EXAMPLES

Build the examples. ON.

ELEMENTS_BUILD_TESTS

Build the test suite; see Testing Elements. OFF.

ELEMENTS_HOST_UI_LIBRARY

The host: cocoa, win32, gtk, x11, wayland or headless. The platform’s own by default; see Host UI Libraries.

ELEMENTS_QUARTZ_2D, ELEMENTS_DIRECT2D, ELEMENTS_CAIRO, ELEMENTS_SKIA

Choose the drawing backend; see Drawing Backends. With none of them set, the platform’s own.

ELEMENTS_RECORDING

Draw with Artist’s recording backend, which keeps a journal of what was drawn and rasterizes nothing. For tests, with the headless host. OFF.

ELEMENTS_ENABLE_LTO

Link-time optimization for the Elements targets. Configure stops with an error if the toolchain does not support it. OFF.

ELEMENTS_HOST_IN_CONSUMER

Leave the host layer out of the library, for a plug-in to compile into each of its own binaries; see Plug-ins. OFF.

Drawing Backends

Elements draws through Artist, which has a backend for each graphics library it supports. One backend is active in a build.

To draw with Skia, for example:

cmake -B build-skia -G Ninja -DCMAKE_BUILD_TYPE=Release -DELEMENTS_SKIA=ON
cmake --build build-skia

Quartz 2D and Direct2D are part of their systems. Cairo on Linux is the system’s, from the packages listed in Setup. Skia everywhere, and Cairo on macOS and Windows, come as prebuilt bundles that configure downloads once and caches, so nothing has to be installed. On Linux, Skia also needs the OpenGL headers:

sudo apt-get install libgl1-mesa-dev libglu1-mesa-dev libegl1-mesa-dev

The prebuilt bundles have requirements of their own: glibc 2.35 or later on Linux, Visual Studio 2022 17.14 or later on Windows, and a deployment target of macOS 11 or later. To build Skia or Cairo from source instead, with vcpkg, or to use libraries of your own, see Artist’s Setup and Installation. Elements' CMakePresets.json has the same two presets as Artist’s for Skia: prebuilt and source.

Host UI Libraries

The host is the layer between Elements and the platform’s windows, events and clipboard. macOS and Windows have one each, Cocoa and Win32. Linux has three:

Host Option and packages

GTK 3, the default

-DELEMENTS_HOST_UI_LIBRARY=gtk. libgtk-3-dev.

X11

-DELEMENTS_HOST_UI_LIBRARY=x11. libx11-dev libxcursor-dev libxrandr-dev.

Wayland

-DELEMENTS_HOST_UI_LIBRARY=wayland. libwayland-dev wayland-protocols libdecor-0-dev libxkbcommon-dev.

These are in addition to the backend’s packages. X11 and Wayland are native hosts, with no toolkit between Elements and the display server. The GTK host runs wherever GTK does, on X11 or on Wayland. The Window page lists where the hosts behave differently.

The headless host has no windows at all: a view lays out and draws into an image, and takes events from direct calls. It is for tests; see Testing Elements.

Sanitizers

The CI runs the test suite weekly under AddressSanitizer with UndefinedBehaviorSanitizer, and under ThreadSanitizer. To do the same, pass the flags to the whole build, the library included, through the environment. With Clang or GCC:

export CFLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer"
export CXXFLAGS="$CFLAGS" OBJCXXFLAGS="$CFLAGS"
export LDFLAGS="-fsanitize=address,undefined"
cmake -B build-asan -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DELEMENTS_BUILD_TESTS=ON
cmake --build build-asan --target elements_test

With MSVC, which has AddressSanitizer only, set CFLAGS and CXXFLAGS to /fsanitize=address.

Two exceptions. The prebuilt Skia is built without AddressSanitizer, and code built with it disagrees with Skia on the layout of some of Skia’s types, so with Skia use UndefinedBehaviorSanitizer alone. And add -fno-sanitize=vptr with Skia: its vptr checks need RTTI, which the prebuilt Skia does not have. ThreadSanitizer reports from the system libraries are suppressed by test/tsan_suppressions.txt:

TSAN_OPTIONS=suppressions=$PWD/test/tsan_suppressions.txt ./elements_test

Plug-ins

An Elements view can live in a window that another program owns, as a plug-in’s editor does in an audio host. On macOS this needs care: the host layer’s Objective-C view class has one name per process, and two plug-ins built with the same Elements would share it.

With ELEMENTS_HOST_IN_CONSUMER=ON, the host layer is left out of the library, and its source files are listed in ELEMENTS_HOST_SOURCES. The plug-in compiles them into each of its own binaries, with its own ELEMENTS_CLASS_PREFIX defined. test/embed/ builds two such libraries into one process and checks that they stay apart; its CMakeLists.txt is a working example. QPlug builds its plug-ins this way.
