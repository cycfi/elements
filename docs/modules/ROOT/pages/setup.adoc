= Setup and Installation

include::common.adoc[]

== Overview

Elements builds with CMake on macOS, Windows and Linux. Each platform has
a default host and a default drawing backend, and on macOS and Windows
the defaults need nothing installed beyond the compiler and CMake. This
page builds the library and its examples with those defaults, and you
are then ready for the xref:tutorials.adoc[Tutorials].

Everywhere, Elements needs:

[cols="1,3"]
|===
| A {cpp}20 compiler
| Clang, GCC, or MSVC. On Windows, Visual Studio 2022 version 17.14 or
  later.

| https://git-scm.com/[Git]
| With submodule support.

| https://cmake.org/[CMake]
| 3.16 or later; 3.21 or later to use the CMake presets.
|===

Elements draws with https://github.com/cycfi/artist[Artist], which comes
with it as a submodule, along with the
https://github.com/cycfi/infra/[Cycfi infra library].

== Getting the Code

[,sh]
----
git clone --recurse-submodules https://github.com/cycfi/elements.git
cd elements
----

The commands on this page run from there. `--recurse-submodules` fetches
Artist and infra. If you cloned without it:

[,sh]
----
git submodule update --init --recursive
----

== Building on macOS

=== Prerequisites

The Xcode Command Line Tools provide the compiler, the system SDK and
Git. If you do not have them:

[,sh]
----
xcode-select --install
----

CMake, and Ninja if you build from the command line, from
https://brew.sh/[Homebrew]:

[,sh]
----
brew install cmake ninja
----

That is all. The default backend is Quartz 2D, which is part of the
system.

=== Build

[,sh]
----
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
----

The examples are in `build/examples/`, each an application bundle: for
example, `build/examples/hello_universe/HelloUniverse.app`.

To work in Xcode instead, generate an Xcode project and open
`build/elements.xcodeproj`:

[,sh]
----
cmake -B build -G Xcode
----

If Xcode stops at code signing, configure with
`-DCMAKE_XCODE_ATTRIBUTE_CODE_SIGNING_ALLOWED=NO`.

== Building on Windows

=== Prerequisites

Visual Studio 2022, version 17.14 or later, with the _Desktop development
with {cpp}_ workload. It includes CMake. Ninja, if you build from the
command line, ships with Visual Studio too, or `choco install ninja`.

The default backend is Direct2D, which uses system libraries only. Its one
other need, a WebP decoder, is fetched and built by CMake. There is nothing
to install.

=== Build

From an _x64 Native Tools Command Prompt for VS 2022_, in the Start menu
under Visual Studio 2022, which has the 64-bit compiler on its path:

[,sh]
----
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
----

The examples are in `build\examples\`: for example,
`build\examples\hello_universe\HelloUniverse.exe`.

To work in Visual Studio instead, generate a solution and open
`build\elements.sln`:

[,sh]
----
cmake -B build -G "Visual Studio 17 2022"
----

== Building on Linux

=== Prerequisites

GCC or Clang with {cpp}20, CMake, and the development packages for the
host and the drawing backend. On Linux, the default host is GTK 3 and the
default backend is Cairo, from the system. On Ubuntu or Debian:

[,sh]
----
sudo apt-get update
sudo apt-get install cmake ninja-build pkg-config \
   libgtk-3-dev libcairo2-dev libfontconfig1-dev libfreetype6-dev \
   libharfbuzz-dev libwebp-dev
----

Elements also has native X11 and Wayland hosts, with packages of their
own; xref:advanced_builds.adoc#_host_ui_libraries[Advanced Builds] lists
them.

=== Build

[,sh]
----
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
----

The examples are in `build/examples/`: for example,
`build/examples/hello_universe/HelloUniverse`.

== The Examples

`examples/` has more than thirty programs, each a single `main.cpp`. The
build makes all of them. Start with `hello_universe` and the
xref:tutorials.adoc[Tutorials], which take five of the examples in order;
the Tutorials page also lists what each of the others shows.

To start a program of your own, copy `empty`: a window with a background
and nothing else. xref:outside_project.adoc[Building Outside the Project]
shows how to build the copy in a folder of its own.

== Going Further

Each platform has more than one backend and, on Linux, more than one
host. xref:advanced_builds.adoc[Advanced Builds] covers choosing them,
along with the build options, sanitizers and link-time optimization.
xref:testing.adoc[Testing Elements] covers the test suite.
